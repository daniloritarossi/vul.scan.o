Why these particular linesPerché proprio queste scelte

  • Settings write is admin-only — the configuration holds secrets and controls where LLM and ticketing traffic goes.La scrittura delle impostazioni è solo per admin — la configurazione contiene segreti e controlla dove va il traffico verso LLM e ticketing.
  • GET /api/scan is an action, not a read — the HTTP verb is misleading; the scanner touches assets with credentials, so viewers are denied.GET /api/scan è un'azione, non una lettura — il verbo HTTP è fuorviante; lo scanner tocca asset con credenziali, quindi i viewer sono esclusi.
  • Editors cannot change assignments — otherwise an editor could widen their own cone.Gli editor non possono modificare le assegnazioni — altrimenti un editor potrebbe allargare il proprio cono.
  • Mixed-host batch imports — an editor importing a report containing out-of-scope hosts gets those rows silently skipped with a skipped_out_of_scope count, so CI pipelines do not break.Import in blocco con host misti — un editor che importa un report contenente host fuori dal cono vede quelle righe saltate in silenzio con un conteggio skipped_out_of_scope, così le pipeline CI non si rompono.

C · Score formulasFormule degli score

Both scores are documented deliberately: you should be able to explain any number the application shows you.

Entrambi gli score sono documentati di proposito: devi poter spiegare qualunque numero l'applicazione ti mostri.

Posture score (0–100, higher is better)Score di postura (0–100, più alto è meglio)

SEV_WEIGHT = { CRITICAL: 1.0, HIGH: 0.7, MEDIUM: 0.4, LOW: 0.2, UNKNOWN: 0.5 }

score = 100                                                          if total_packages == 0se total_packages == 0
score = max(0, round(100 * (1 - min(1.0, weighted / total * 1.3))))   otherwisealtrimenti

100 means nothing vulnerable was found. The score falls as a larger share of the installed base carries CVEs, weighted by how severe they are.

100 significa che non è stato trovato nulla di vulnerabile. Lo score scende man mano che una quota maggiore dei pacchetti installati presenta CVE, pesati per gravità.

Contextual risk index (0–100, higher is worse)Indice di rischio contestuale (0–100, più alto è peggio)

per finding:per ogni finding:
  base      = SEV_WEIGHT[severity]
  exploit   = 1.0 + (1.5 if CVE in CISA_KEVse il CVE è in CISA_KEV) + max(EPSS)     # EPSS ∈ 0..1
  exposure  = 1.4 if a matching service port answeredse una porta di servizio ha risposto else 1.0
  finding_risk = base * exploit * exposure

per asset:per ogni asset:
  raw        = sum(finding_risk)
  asset_raw  = raw * ctx_mult              # environment + internet-facing + criticality
  risk_index = round(100 * (1 - exp(-asset_raw / 8.0)))     # saturatingcon saturazione

buckets:fasce:  >= 75  CRITICAL RISK      45..74  HIGH RISK      < 45  lowerinferiore

Three consequences worth internalisingTre conseguenze da interiorizzare

  • KEV dominates. A single known-exploited CVE multiplies its finding by 2.5 before context is applied. That is intentional: it is being exploited right now.Il KEV domina. Un solo CVE noto come sfruttato moltiplica il proprio finding per 2,5 prima ancora del contesto. È voluto: è sfruttato adesso.
  • The curve saturates. The exponential means an asset with 40 findings does not score four times an asset with 10. Past a point an asset is simply “very bad”, and quantity stops discriminating.La curva satura. L'esponenziale fa sì che un asset con 40 finding non valga quattro volte uno con 10. Oltre una certa soglia un asset è semplicemente «molto grave» e la quantità smette di discriminare.
  • Context is a multiplier, not an addition. Marking an asset production, internet-facing and criticality 5 amplifies everything it carries — which is why filling those three fields is the highest-value five minutes on the /risk page.Il contesto è un moltiplicatore, non un'addizione. Marcare un asset come produzione, esposto a internet e criticità 5 amplifica tutto ciò che porta — ed è per questo che compilare quei tre campi sono i cinque minuti più redditizi della pagina /risk.

D · End-to-end workflowsFlussi di lavoro end-to-end

Weekly vulnerability review (about 30 minutes)Revisione settimanale delle vulnerabilità (circa 30 minuti)

  1. /intel → ASSETS = ALL → RUN FULL POSTURE SCAN
  2. /risk → confirm EPSS live → read the top five rows → check CHANGE vs PREVIOUS RUN.verifica EPSS live → leggi le prime cinque righe → controlla CHANGE vs PREVIOUS RUN.
  3. /findings → click SLA BREACHED → triage each row, create tickets.clicca SLA BREACHED → esamina ogni riga, crea i ticket.
  4. /intel → RESOLVE on the top vulnerable components → record the target versions in the tickets.sui componenti più vulnerabili → annota le versioni obiettivo nei ticket.
  5. /audit → export CSV for the weekly report.esporta il CSV per il report settimanale.

Onboard a new team with a scoped coneInserire un nuovo team con un cono dedicato

  1. /admin → create the group (for example team-payments).crea il gruppo (per esempio team-payments).
  2. /admin → INVITE USER for each member with role editor → add them to the group.per ogni membro con ruolo editor → aggiungilo al gruppo.
  3. /assets → for each of their assets, ASSIGNED → tick the group → SAVE.per ciascuno dei loro asset, ASSIGNED → spunta il gruppo → SAVE.
  4. Have one member sign in and confirm they see exactly their assets and nothing else.Fai accedere un membro e verifica che veda esattamente i suoi asset e nulla di più.

Wire CI scanner output into the lifecycleCollegare l'output di uno scanner CI al ciclo di vita

  1. In CI produce the report, for example trivy image -f json -o trivy.json $IMAGE.In CI genera il report, per esempio trivy image -f json -o trivy.json $IMAGE.
  2. Upload it in /findings → IMPORT SCANNER REPORT, or call POST /api/findings/import from the pipeline with the session cookie.Caricalo in /findings → IMPORT SCANNER REPORT, oppure chiama POST /api/findings/import dalla pipeline con il cookie di sessione.
  3. Set asset_ip so the findings attach to the right host and flow into /risk.Imposta asset_ip perché i finding si aggancino all'host giusto e confluiscano in /risk.
  4. Duplicates across tools collapse into one finding by fingerprint — it is safe to run Trivy and Grype together.I duplicati fra strumenti collassano in un unico finding per fingerprint — puoi tranquillamente usare insieme Trivy e Grype.
  5. Enable ticketing so triage produces real issues in the team's tracker.Attiva il ticketing perché il triage produca issue reali nel tracker del team.

Answer a supply-chain questionRispondere a una domanda di supply chain

  1. /sbom → Search purl, CPE, licence… → type the component name.digita il nome del componente.
  2. Enable GROUP BY COMPONENT to see one row per version with the affected asset count.Attiva GROUP BY COMPONENT per vedere una riga per versione con il numero di asset coinvolti.
  3. Switch the vulnerability filter to Vulnerable only.Imposta il filtro vulnerabilità su Vulnerable only.
  4. Export CYCLONEDX and attach it to the answer.Esporta CYCLONEDX e allegalo alla risposta.

Prove compliance posture (NIS2 / OWASP)Dimostrare la postura di conformità (NIS2 / OWASP)

  1. /findings → read the NIS2 · ART. 21(2) MEASURES and OWASP TOP 10 bars — both computed at runtime from live findings.leggi le barre NIS2 · ART. 21(2) MEASURES e OWASP TOP 10 — entrambe calcolate a runtime dai finding vivi.
  2. Filter by a specific NIS2 measure to list exactly which findings sit behind that bar.Filtra per una misura NIS2 specifica per elencare esattamente quali finding stanno dietro quella barra.
  3. /audit → confirm LEDGER VERIFIED → export the period.verifica LEDGER VERIFIED → esporta il periodo.
  4. /sbom → export the standard SBOM for the same period's run.esporta la SBOM standard della run dello stesso periodo.

G · AI transparency (EU AI Act, Regulation 2024/1689)Trasparenza AI (AI Act UE, Regolamento 2024/1689)

The application uses general-purpose AI models for four advisory tasks: CVE risk summaries, affected-version extraction from advisory text, product identification when regex heuristics fail, and triage hints. It implements no prohibited practice under Article 5 and falls in no Annex III high-risk category — it supports patch prioritization on IT assets and takes no decision affecting natural persons. The resulting tier is minimal/limited risk, so the applicable measures are transparency and AI literacy.

L'applicazione usa modelli di AI general-purpose per quattro compiti di supporto: riepiloghi del rischio CVE, estrazione della versione affetta dal testo degli advisory, identificazione del prodotto quando le euristiche regex falliscono e suggerimenti di triage. Non implementa alcuna pratica vietata dall'articolo 5 e non ricade in alcuna categoria ad alto rischio dell'Allegato III — supporta la prioritizzazione delle patch su asset IT e non prende decisioni che riguardano persone fisiche. La fascia risultante è rischio minimo/limitato, quindi le misure applicabili sono trasparenza e alfabetizzazione all'AI.

  • Every AI-generated text carries an AI-GENERATED badge with a disclaimer tooltip.Ogni testo generato dall'AI porta un badge AI-GENERATED con tooltip di avvertenza.
  • LLM-derived advisory extractions are tagged [AI] in the live scan log, including the provider and model name.Le estrazioni di advisory derivate dall'LLM sono marcate [AI] nel log di scansione live, con nome del provider e del modello.
  • With Ollama inference is fully local. With Claude, prompts contain only product names, version strings and public CVE identifiers — never asset IP addresses, hostnames, credentials or personal data.Con Ollama l'inferenza è interamente locale. Con Claude i prompt contengono solo nomi di prodotto, stringhe di versione e identificativi CVE pubblici — mai indirizzi IP degli asset, hostname, credenziali o dati personali.
  • EPSS is a third-party machine-learning model; only CVE identifiers are sent to FIRST.org, nothing about your assets.EPSS è un modello di machine learning di terze parti; a FIRST.org vengono inviati solo identificativi CVE, nulla dei tuoi asset.
  • All AI output is advisory: scan verdicts, CVE matching and SLA tracking never depend solely on a model answer. Verify version constraints against the linked CVE and OSV records before acting.Tutto l'output AI è indicativo: verdetti di scansione, matching CVE e tracciamento SLA non dipendono mai unicamente dalla risposta di un modello. Verifica i vincoli di versione sui record CVE e OSV collegati prima di agire.
  • A model failure degrades gracefully: the application returns empty summaries rather than blocking scans.Un guasto del modello degrada in modo controllato: l'applicazione restituisce riepiloghi vuoti invece di bloccare le scansioni.
